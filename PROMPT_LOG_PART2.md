### 19. LocalStorage drafts "not working" — two root causes found and fixed
- **My prompt:** "check the LocalStorage again, it is not working"
- **Diagnosis:** Two separate causes. First, my production builds and `next start` test servers were writing to the same `.next` folder the user's long-running `next dev` server was serving, leaving its chunks stale so pages could fail to hydrate — with no client JS, typed text never reached React state, so nothing saved (it looked exactly like broken localStorage). The dev server was killed, `.next` wiped, and a fresh `next dev` started on port 3000. ### Example 2 — Null and invalid request bodies return 400, not 500
- **Proposal:** "can you check again and confirm how both APIs for contact and blog handle null as the request body. I tested it myself, it is currently returning 500. Make sure they reject invalid requests with 400, then test both endpoints."
- **My decision:** Added one shared body reader, `readJsonBody` in `lib/http.js`, used by all three POST endpoints (`/api/contact`, `/api/contacts`, `/api/blogs`). It first parses the JSON (malformed or missing → 400 "Request body must be valid JSON.") and then requires a non-null, non-array object (→ 400 "Request body must be a JSON object.") before the domain validators run.
- **Reason:** `request.json()` parses the text `null` successfully; the validators then crashed on `null.name` with an uncaught TypeError, which the server reports as 500 — a server-error code for a client mistake. Rejecting the shape up front returns the correct 4xx class and keeps the rule in one place for all three endpoints.
- **Relevant file:** `lib/http.js`, `app/api/contact/route.js`, `app/api/contacts/route.js`, `app/api/blogs/route.js` (historical status when this example was recorded: working tree, commit pending).
- **Check performed:** A curl matrix over all three POST endpoints with seven body shapes: `null`, `[1,2]`, `"hi"`, `5`, malformed `{bad`, no body at all, and a valid JSON object.
- **Actual result:** `null`, array, string, and number bodies all returned `400` with `{"errors":{"form":"Request body must be a JSON object."}}`; malformed and missing bodies returned `400` with `{"errors":{"form":"Request body must be valid JSON."}}`; the valid object returned `201`. No `500` anywhere — versus the confirmed `500` for a `null` body before the fix.
